# Eleven Winters

**Separating weather, farm fires and fireworks in India's PM2.5, 2016–2026.**
An open, reproducible exploratory data analysis with a paper, a companion website and a
pre-registered forecast for Diwali 2026.

- Website: https://krishnav1412.github.io/eleven-winters/
- Paper (PDF): [`paper/eleven-winters.pdf`](paper/eleven-winters.pdf) · LaTeX for submission: [`paper/paper.tex`](paper/paper.tex)
- Locked forecast: [`prereg/`](prereg/)

## What this study does

Delhi's winter air is blamed on three things that arrive together: stagnant weather,
smoke from paddy-residue burning in Punjab and Haryana, and Diwali fireworks. We use three
things that vary from year to year to separate them: Diwali's lunar date, which moves
across the burning season; Delhi's firecracker rules, which changed four times; and the
timing of crop burning itself.

| Part | Question | Method |
|---|---|---|
| A | How much of the winter rise is weather? | LightGBM weather normalisation per site (Grange et al., 2018), year-blocked cross-validation |
| B | What does Diwali add, once weather and farm smoke are removed? Did the bans work? | Hourly business-as-usual model with a wind-aware fire index, out-of-fold by ISO week; placebo nights; censoring-aware metrics |
| C | Do falling fire counts mean less burning? | VIIRS day vs night overpass shares; season-by-season coupling of Delhi PM2.5 to upwind fires; ground test at Punjab and Haryana monitors |
| D | Can the method predict? | Forecast for Diwali 2026, locked and checksummed before the festival |

## Data

All public:

- **CPCB and US mission monitors**, hourly, via the [OpenAQ archive on AWS](https://registry.opendata.aws/openaq/). Station list: `config/stations.csv`.
- **NASA FIRMS** active fires, VIIRS S-NPP 375 m and MODIS, country-year files.
- **ERA5** hourly weather via the [Open-Meteo](https://open-meteo.com) archive API.
- **geoBoundaries** state boundaries for Punjab, Haryana, Delhi and Chandigarh.

Note: the OpenAQ archive has no CPCB-network data from late 2022 to early 2025. The US
mission monitors cover that period.

## Reproduce

Requires Python 3.11+.

```bash
git clone https://github.com/krishnav1412/eleven-winters
cd eleven-winters
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
cp .env.example .env               # add a free OpenAQ API key; set EW_DATA_DIR
ew download                        # ~2 GB: station index, archive, fires, weather (weather is rate-limited)
ew all                             # clean, model, analyse, figures, paper, website
pytest                             # unit tests
```

Each stage can also run alone: `ew panel`, `ew parta`, `ew partb`, `ew partc`, `ew figures`,
`ew paper`, `ew site`. The forecast is locked with `ew forecast` and is deliberately not part of
`ew all`, so the published record cannot be regenerated by accident.

## Layout

```
config/            settings, study cities, events and firecracker rules (with sources), station list
src/elevenwinters/
  ingest/          OpenAQ, FIRMS, Open-Meteo downloaders
  qc.py            units, hourly averaging, quality flags
  panel.py         site, city and weather tables
  fires.py         fire detections, fixed-source mask, wind-aware fire index
  models.py        LightGBM normalisation and out-of-fold baselines
  analysis/        parta (weather), partb (Diwali), partc (fires), forecast
  figures/         one Altair spec per figure -> PDF/PNG for the paper, JSON for the site
  report.py        every number quoted in the paper and site
  paper.py         paper -> HTML, PDF, LaTeX
  site/            website builder and templates
results/           small result tables (CSV/JSON), committed
paper/             paper template, references, figures, built outputs
docs/              the built website (GitHub Pages)
prereg/            the locked Diwali 2026 forecast and its checksum
tests/             unit tests
```
